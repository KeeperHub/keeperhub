### Foundations — Import Schema Hardening (KEEP-368, security gate)

- [ ] **SEC-01**: Client-side file-size cap of 1 MB on JSON upload in `WorkflowIOOverlay` import tab. Files larger than 1 MB show inline error and never call `file.text()`.
- [ ] **SEC-02**: Server-side hard byte cap on `app/api/workflows/import/route.ts` reads `Content-Length` header before `request.json()`; rejects >1 MB with HTTP 413.
- [ ] **SEC-03**: `lib/workflow/export-schema.ts` replaces `.passthrough()` with `.strict()` on `nodeDataSchema` and `exportNodeSchema` outer envelopes. Inner `data.config` retains `.passthrough()` for forward-compat only where required.
- [ ] **SEC-04**: Schema adds `.max()` caps on free-text fields: `name` 200 chars, `description` 2000 chars, `label` 500 chars; caps `nodes.length` at 200 and `edges.length` at 500.
- [ ] **SEC-05**: Imported workflows containing `code` step nodes with non-empty user code prompt the user for explicit confirmation before save (or are rejected outright pending Phase 42 planning decision).
- [ ] **SEC-06**: Unit test `tests/unit/workflow-import-schema.test.ts` rejects: 100 MB file, oversize description, schema with `.passthrough()` keys, 201-node workflow, non-https webhook URL.

## Out of Scope

- **New `/api/marketplace` REST endpoint** — extending `/api/mcp/workflows` with `?sort=` is sufficient. Two endpoints would split the catalog surface and confuse agent vs UI consumers.
- **Marketplace as a Hub tab** — Hub (free templates, vote-driven) and Marketplace (paid services, popularity-driven) have different mental models, sort semantics, and CTAs. Mixing them in one surface forces a sort widget that handles both vote-score and call-count, and a CTA that switches between "Vote" and "Pay-per-call". Resolved in research.
- **`?tag=` query param for canonical tag URLs** — `/hub/tags/[tag]` path segment is the canonical form so per-tag `generateMetadata` and `<link rel="canonical">` work.
- **localStorage for view preference** — cookie is required for first-paint correctness in RSC. Hydration mismatch is the symptom of the wrong choice.
- **Wrapping the entire template card in `<a>`** — breaks nested-button accessibility for vote / Use-template controls. CSS pseudo-element overlay is the consensus accessibility pattern.
- **Anonymous-signup auto-trigger from Use-template** — the existing fallback at `workflow-template-grid.tsx:71-73` provisions an anonymous user but `/api/workflows/import` returns 403. Replace with explicit auth dialog.
- **Real-time / websocket-driven leaderboard** — 5-minute TTL is sufficient for v1.11. Real-time invites cache-invalidation complexity for marginal UX gain.
- **Server-component split for the sidebar** — the sidebar already needs `useSession`, panel state, and overlay handlers; a server-component wrapper adds layers without removing the client island.
- **Two side-by-side modal overlays for import + export** — the merge into `WorkflowIOOverlay` with shadcn Tabs is the entire point of KEEP-368.
